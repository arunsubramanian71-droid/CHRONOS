# Teaching notes: one per component (C1 to C18)

Each note answers: what is it in CHRONOS terms, how would you explain it in a minute, where is the code and what runs it. They are the
short notes the specification's definition of done asks for; `VIVA_GUIDE.md` has the cross-cutting concepts (clocks, cuts, event sourcing).
Every public type also carries a Javadoc comment in the same spirit (checked: all 83 public types have one).

| # | Component | In one minute | Code | See it run |
|---|---|---|---|---|
| C1 | **Node SDK** | The narrow door between an application and the world. A node is a single-threaded handler (`onStart`, `onMessage`, `onTimer`, `onClientInput`, `onRestart`); all its memory is `ctx.state()` (volatile zone lost on crash, durable zone kept); all its effects go through `NodeContext`. Because nothing else can influence a node, it is a function of its inputs: that is what makes everything else possible (D-01). | `chronos-sdk` | `Tutorial.java`, `chronos run tutorial` |
| C2 | **Simulation engine** | One thread, one virtual clock, one agenda ordered by (due time, target node, kind rank, identity). Each step takes one item, runs one handler, and commits one atomic group of events. Time jumps; nothing sleeps. | `Engine.step` | `chronos run pingpong`, `show --diagram` |
| C3 | **Decision source** | The single seam for every non-deterministic choice (latency, random draws, probabilistic faults). Record mode derives answers from the seed by hashing the *identity* of the thing decided, so message `p#17` gets the same fate in every timeline; replay mode reads them from the log; branch mode does both. | `DecisionSource`, `RecordDecisionSource`, `ReplayDecisionSource`, `BranchDecisionSource` | `chronos determinism re --jvm 2` |
| C4 | **Clock service** | Lamport and vector clocks, stamped from the merge of all causal parents (messages, but also faults, witnesses and omissions). Lamport: "if X happened before Y then L(X) < L(Y)", not the converse. Vector: "X before Y exactly when V(X) < V(Y)". The `env` slot is last. | `ClockService`, `VectorClock` | `show T0` (clock columns), laws M3/M4 |
| C5 | **Event recorder** | Turns what the engine did into immutable events with deterministic ids and causal parents, and hands each step's group to every sink (store writer, graph builder, replay verifier) atomically. | `Recorder`, `Event` | `show T0 --json` |
| C6 | **Event store** | The log is the truth: segmented JSON lines, each step group closed by a checksummed commit line, checkpoints, a catalogue, derived indexes. A crash can only lose the unfinished last step, which is detected and discarded. A branch stores only its own suffix. | `TimelineStore`, `TimelineWriter`, `TimelineIndex` | `PersistenceTest` (kill -9), `chronos reindex --check` |
| C7 | **Causal graph engine** | The events as a DAG on dense arrays: causal past (the suspects for a failure), causal future (what an event could have influenced), happens-before, concurrent, shortest "why" path that prefers certain edges. A self-check proves vector clocks and reachability agree. | `CausalGraph` | `inspect --why`, `--effects`, law M4 |
| C8 | **State and snapshot manager** | State is canonical data; a digest after every step, a full record when it changed; the last writer of every field. Any past state is rebuilt by reading the log (no application code runs). Checkpoints are whole-world images that can be restored and run on. | `NodeState`, `Engine.captureImage/restore`, `TimeTravelSession.stateOf` | `inspect --goto violation --world`, laws M2/M5 |
| C9 | **Replay engine** | Re-executes the application with the replay decision source and compares every regenerated event with the recording; the first difference is a determinism violation with a field-by-field report. It can resume from a checkpoint and stop at a breakpoint. | `ReplayEngine`, `VerifyingSink` | `chronos verify T0`, `chronos run bad` then `verify` |
| C10 | **Time-travel session** | A cursor over the log: goto, step, back, next/previous on a node, find, state, in-flight messages, timers, clocks, why, effects, watch, diff. Looking is cheap and read-only; acting (branching) is explicit. | `TimeTravelSession` | `chronos session T0` |
| C11 | **Timeline manager** | Timelines form a tree. A branch restores the nearest checkpoint, replays the prefix (verifying as it goes), applies interventions and runs on under the branch decision source. It can only start between steps, after boot. | `TimelineManager` | `chronos branch`, `chronos ls` |
| C12 | **Fault injector** | Faults are first-class, deterministic and recorded: partition, drop, delay, duplicate, reorder, crash, restart, pause, clock skew, slow link, probabilistic; triggered by time, by an event, by a message id, by the n-th message, by chance (identity-hashed) or by node state. Applied only by the engine, never inside node code; a node can only see their consequences. | `FaultInjector`, `FaultRule`, `FaultPlan` | `chronos run re --fault ...`, `chronos campaign` |
| C13 | **Counterfactual engine** | "Change one thing in the past and see whether the failure survives." Five verdicts. Independent branches run in parallel, each in its own world. It is evidence about the simulated world, not proof about reality, and a single-change test can miss overdetermined failures. | `CounterfactualEngine`, `InterventionSearch` | `chronos branch`, `chronos causes`, `chronos search` |
| C13b | **Systematic explorer and incident bundles** | Random testing says "found one"; systematic exploration says "here is every minimal schedule of this size, and here is what I did not cover". Each counterexample is a reproducible document; any timeline can leave the machine as one validated file. | `SystematicExplorer`, `Counterexample`, `IncidentBundle` | `chronos explore`, `chronos incident export` |
| C14 | **Comparator** | Aligns two timelines by event id, classifies differences (Same, Changed, Missing, Extra, Reordered), finds the roots separately inside each timeline (taint never crosses over), and names the earliest root as the first causal divergence, with the path from it to the failure. "First" means causally first, not first in the log. | `TimelineComparator` | `chronos compare`, `chronos report --against` |
| C15 | **Invariant checker** | Global rules checked by the engine after every step through a recording accessor; the violation event carries WITNESS edges to the last writers of exactly the fields the rule read, so the "why" chain starts from the state that mattered. | `Invariant`, `RecordingView` | `chronos run re` (single-primary) |
| C16 | **Presentation layer** | Text, DOT and JSON exports, the self-contained HTML report (inline SVG, no network), and a read-only live viewer. It holds no logic of its own: it only calls the components above. | `Cli`, `HtmlReport`, `Viewer`, `Exports` | `chronos report`, `chronos serve` |
| C17 | **Demo applications** | Ping-pong, the causal-ordering demo, RE (the replicated store with a seeded split-brain), lost update, blocked commit, a correct control, gossip, a deliberately nondeterministic "bad citizen", and the tutorial. They are also the known-answer bug library. | `chronos-demo` | `chronos demo` (24 checks) |
| C18 | **Test and benchmark harness** | Laws M1 to M14, known-answer tests, golden files, chaos soak, analyser mutation tests, JMH and whole-system benchmarks, and build-time rules that fail the build if the architecture or the determinism hygiene is violated. | `chronos-cli/src/test`, `chronos-bench` | `mvn package`, `chronos-bench.jar all` |
